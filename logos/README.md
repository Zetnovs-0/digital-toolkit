# Your own logos

All logos live in this folder and are served **directly from you** — no CDN needed.
They take priority over every external source (Simple Icons, Unavatar, Google favicons).

## How it works

- `manifest.js` maps each tool's **exact name** (as shown on the site) to a file here.
  It's loaded by `index.html` via a `<script>` tag, so it works over http(s) **and**
  when you just double-click `index.html` from disk.
- `fetch_logos.sh` downloads every logo automatically and regenerates `manifest.js`.
  Re-run it anytime: `bash fetch_logos.sh`

## Add or replace a logo by hand

1. Drop the file in this folder, e.g. `vivaldi.png` (SVG preferred, ~128px+)
2. Add an entry in `manifest.js`:

```js
window.LOCAL_LOGOS_MANIFEST = {
  version: 2,               // bump when you replace files (cache-buster: ?v=2)
  logos: {
    "Vivaldi": "vivaldi.png",
    // ...existing entries
  },
};
```

3. Bump `version` whenever you replace an existing file, so browsers refetch it.

## Notes

- Keys must match the item name exactly (`"Google Chrome"`, not `"Chrome"`).
  This includes extension names (`"uBlock Origin"`), browser names
  (`"Mullvad Browser"`), and OS labels (`"Linux Mint"`, `"Pop!_OS"`).
- If a name isn't in the manifest (or the file is missing), the site silently
  falls back to the CDN chain — nothing breaks.
- The 60 entries generated by `fetch_logos.sh` came from Simple Icons (SVG),
  DuckDuckGo/Google favicons, and two direct sources (XMCL, Clonezilla).
  Favicons are lower quality — swap any of them for a crisp SVG when you can.
- Regenerating with `fetch_logos.sh` resets `version` to 1; bump it if you
  replaced files and need visitors' browsers to refetch.
